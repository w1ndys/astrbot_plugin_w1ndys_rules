# astrbot_plugin_w1ndys_rules

AstrBot 插件：w1ndys 的群管。关键词回复、欢迎语、入群验证、邀请树由代码处理；违禁词先由
代码匹配全局触发词，命中后才让当前大模型按固定准则和插件 Pages 样本回答「是/否」。
入群验证私聊交码，白天每 2 小时提醒，提醒超过 4 次仍未验证则踢出。

从 monorepo `w1ndys-astrbot-plugins` 拆出，独立成仓。功能开没开由插件 Pages「控制台」的群号名单控制，
空名单即关。不抽跨插件公共模块。


## 关键词回复

- 群员发一条消息，内容与某个关键词完全相同，机器人就回预设内容。
- 不 @ 机器人、不唤醒，照样回复，也不会触发模型。
- 每个群默认关闭。要开启时在插件 Pages「控制台」的「全局配置」里添加该群并勾选「关键词」，空名单则都不开。

- 表格录入在插件 Pages「控制台」的「关键词」：一张表管全部群，可按群号过滤、翻页。群里不再认自然语言增删改查，也不认「关键词 批量」。

## 违禁词

- 每个群默认关闭。要开启时在插件 Pages「控制台」的「全局配置」里添加该群并勾选「违禁词」，空名单则都不开。

- 触发词全局保存在 `rules.db`。管理员只在插件 Pages「控制台」的「违禁触发词」增删改查，对所有群生效。
- 违禁样本和判断准则在插件 Pages「控制台」的「全局配置」：准则是单行说明，样本是可换行文本。不要在 QQ 里粘贴原始样本。
- 同一页还保存提醒文案、禁言时间和飞书 Webhook。
- 群消息包含任一触发词后才送模型判断；英文匹配不区分大小写。只有模型整句回答「是」才撤回、禁言并提醒。
- 纯图片也会进违禁判断。本地用 QReader 检出二维码即违禁，不看载荷、不送模型。没装 QReader 则这一层跳过，继续转写。
- 图片转写用原图本地 OCR（RapidOCR），不读协议 payload。有可见文字就送「是/否」模型，不走触发词。没装或认不出字则不送。表情贴纸不跑 OCR，但仍过二维码层。系统提示与文本路同一套准则和样本。


- 插件 Pages「控制台」的「违禁日志」可按群、成员、原因筛选命中记录。列表不带原文；点开一条才加载文本、卡片和图。
- 每一行可加入或移出本群白名单、全局白名单、本群黑名单、全局黑名单。两张表结构相同，全局行的群号键都是 `global`。
- 本群行只影响该群，全局行影响所有群。同一范围加白会移出同范围黑名单，拉黑会移出同范围白名单。任一黑名单压过任一白名单。
- 白名单使该群的文本、OCR、二维码和群名片跳过。拉黑不踢人。
- 功能开关、欢迎语文案、违禁准则、样本、禁言秒数、提醒、飞书 webhook、规则开关都存在 `rules.db` 的 `plugin_setting`。Pages 保存后立即生效。schema 只留着让 AstrBot 加载插件，热路径不读它。
- 插件 Pages「控制台」的「全局配置」按群号勾选功能，并手写欢迎语文案、违禁样本、飞书 webhook。增删改查只走这一页，官方插件配置页不展示字段。


## 欢迎语

- 每个群默认关闭。要开启时在插件 Pages「控制台」的「全局配置」里添加该群并勾选「欢迎语」，空名单则都不发。
- 全局默认文案在插件 Pages「控制台」的「全局配置」里「入群欢迎语文案」。本群没单独设置时用这一句；留空则发「欢迎入群~」。
- 群主、群管理员或 AstrBot 管理员可在群里发「欢迎语 设置」写本群文案，发「欢迎语」查看。只发命令不写文案则本群关闭，优先于开启名单。


- 欢迎语不发到群里。没开入群验证时，入群也不发欢迎语。
- 和入群验证同时开时，入群只禁言并发验证说明。私聊交码通过后，私聊只回这一群的欢迎语；这一群没有欢迎语时，私聊仍回「已通过人机验证。」
- 其他管理员在群里解禁并视为通过时，群里先发这一群的欢迎语（有文案才发），再报「已通过人机验证。」。不私聊这条欢迎语。管理员工具通过时，群里仍只报通过句，欢迎语私聊。交码失败、拒绝、踢出、退群都不发。
- 通过后只撤回验证说明，不撤欢迎语。

## 入群验证

- 每个群默认关闭。要开启时在插件 Pages「控制台」的「全局配置」里添加该群并勾选「入群验证」，空名单则都不验证。

- 名单里的群有人入群会立刻禁言 30 天，并在群里单独发验证码，要求私聊我交码。

- 私聊消息里带着这串码就算通过；码前后不能是数字，避免把更长号码里的一段当成交码。复制整段说明也可以。群里发码不算。
- 自己交码通过后：解禁、撤回群里的验证提醒，并**私聊**回这一群的欢迎语；这一群没有欢迎语时，私聊仍回「已通过人机验证。」群里不发欢迎语，也不再另报通过。
- 仍处于 pending 时，入群后每 2 小时群里再提醒一次并换新码（旧码立刻作废）。入群那条说明不算提醒。只在北京时间 8:00–22:00 发（含 8 点，不含 22 点）；夜里到期的等到早上 8 点再发，夜里不换码、不踢人。每次提醒写明这是第几次、还剩几次机会，发出后撤回上一条。
- 白天提醒已满 4 次仍未验证，下一次到期不再发码，直接移出群（不拒绝以后再入群），撤回上一条提醒，并在群里说明已移出。踢失败则保留 pending，下一拍再试。
- 停机期间错过的提醒不连发，重启后只补当前这一档。
- 同时多个群待验证时，按码匹配对应那一群。图片、语音不当交码。
- 群消息仍先走违禁词。待验证的人若还能发言，广告也会撤回。
- 管理员带唤醒前缀后，可用自然语言扫描、通过、拒绝本群待验证的人。扫描会在群里 @；通过会解禁、撤回提示，并在群里 @ 该成员；拒绝只关 pending、撤回提示，不踢人。
- 人退群或被踢会清掉 pending 并撤回当前提醒。其他管理员解开禁言视为通过，并撤回提示；机器人自己解禁或禁言到期不算。
- 管理员拒绝、拉黑都不踢人。只有验证提醒超过 4 次会踢出。

## 邀请树

- 每个群默认关闭。要开启时在插件 Pages「控制台」的「全局配置」里添加该群并勾选「邀请树」，空名单则都不记。
- 名单里的群入群会记下「谁拉了谁」；退群不删边，再进覆盖成最新邀请人。

- 管理员带唤醒前缀后，可查某人的上线链（一直往上追）和整条下线（递归整棵树）。

## 一个必须知道的坑

AstrBot 在唤醒检查阶段会把唤醒前缀从消息开头剥掉。如果某个部署把唤醒前缀配成
「卷卷」，那么群员发「卷卷你好」到最后只剩「你好」参与匹配。因此**关键词不能以
唤醒前缀开头**，否则它永远匹配不到。插件在写入时会拦下这类关键词并说明原因。

## 匹配口径

整条消息完全相等才算命中，不做包含匹配，也不放宽大小写和空白。匹配用的是
AstrBot 解析后的纯文本，不是 OneBot 原始 `raw_message`，所以带 @ 或图片的消息
只比对文本部分。

## 开发

改 Pages：`cd dashboard && npm install && npm run build`，产物在 `pages/console/`。
改完插件后需要让 AstrBot 重新加载。注意 AstrBot 的热重载被环境变量守卫：

```python
if os.getenv("ASTRBOT_RELOAD", "0") == "1":
    asyncio.create_task(self._watch_plugins_changes())
```

没设 `ASTRBOT_RELOAD=1` 时文件监视根本不会启动，改代码必须重启容器才生效。
