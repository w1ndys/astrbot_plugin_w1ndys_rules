# astrbot_plugin_w1ndys_rules

AstrBot 插件：群规。关键词回复由代码确定性匹配；违禁词先由代码匹配全局触发词，
命中后才让当前大模型按固定准则和 WebUI 样本回答「是/否」。入群验证在群里交码，
不踢人。

从 monorepo `w1ndys-astrbot-plugins` 拆出，独立成仓。群开关由本插件自己管，
不抽跨插件公共模块。

## 关键词回复

- 群员发一条消息，内容与某个关键词完全相同，机器人就回预设内容。
- 不 @ 机器人、不唤醒，照样回复，也不会触发模型。
- 每个群的开关默认关闭，需要管理员在群里发 `关键词 开` 打开，不用带唤醒前缀。
- 管理员可以用自然语言增删改查关键词，例如「添加关键词 原神 回复 好玩」。这条要带唤醒前缀，因为要进模型。
- 一次贴很多条时用 `关键词 批量`，不经过模型，也不用带前缀。后面换行，一行一条，关键词和回复用 `|` 分开。已有关键词会报冲突，不会覆盖。

## 违禁词

- 每个群的开关默认关闭，管理员在群里发 `违禁词 开` 或 `违禁词 关`，不用唤醒前缀。
- 触发词全局保存在 `rules.db`。管理员在群里带唤醒前缀后，可用自然语言增删改查；只在群会话里改，结果对所有群生效。
- 违禁样本和判断准则在 WebUI：准则是单行说明，样本是可换行文本。不要在 QQ 里粘贴原始样本。
- WebUI 还保存提醒文案、禁言时间和飞书 Webhook。
- 群消息包含任一触发词后才送模型判断；英文匹配不区分大小写。只有模型整句回答「是」才撤回、禁言并提醒。
- 近 7 天在本群发过言的人，即使命中触发词也不送模型。刚装上没有历史，全员先当不活跃。
- WebUI 测试页读取全局触发词和 WebUI 样本；测试不会执行群内处置。

## 欢迎语

- 每个群的开关默认关闭，管理员在群里发 `欢迎语 开` 或 `欢迎语 关`，不用唤醒前缀。
- 设置文案发 `欢迎语 设置`，同一行或换行写下正文。整句发 `欢迎语` 可查看当前文案。
- 打开开关后，有人入群会发送已设置的文案；还没设过则发送「欢迎入群~」。
- 和入群验证同时开时，欢迎语和验证说明合成一条发出。

## 入群验证

- 每个群的开关默认关闭，管理员在群里发 `入群验证 开` 或 `入群验证 关`，不用唤醒前缀。
- 打开后，有人入群会生成 6 位数字码，并在群里说明：请发一条包含验证码的消息。入群时不立刻禁言。
- 消息里带着这串码就算通过；码前后不能是数字，避免把更长号码里的一段当成交码。复制整段说明也可以。
- 待验证的人发了不含码的文本会被禁言。秒数在 WebUI「入群验证禁言秒数」里配，没填按 600 秒，填 0 则不禁，超过 QQ 30 天会夹住。图片、语音、斜杠指令不当验证发言。
- 群消息先走违禁词再走入群验证。待验证的人发广告也会撤回，不会因为验证失败提前结束。
- 通过后解禁，并开始记近 7 天发言。失败禁言不记活跃。
- 管理员带唤醒前缀后，可用自然语言扫描、通过、拒绝本群待验证的人。扫描会在群里 @；通过会解禁；拒绝只关 pending，不踢人。
- 人退群或被踢会清掉 pending。其他管理员解开禁言视为通过；机器人自己解禁或禁言到期不算。
- 本插件不踢人。

## 一个必须知道的坑

AstrBot 在唤醒检查阶段会把唤醒前缀从消息开头剥掉。如果某个部署把唤醒前缀配成
「卷卷」，那么群员发「卷卷你好」到最后只剩「你好」参与匹配。因此**关键词不能以
唤醒前缀开头**，否则它永远匹配不到。插件在写入时会拦下这类关键词并说明原因。

## 匹配口径

整条消息完全相等才算命中，不做包含匹配，也不放宽大小写和空白。匹配用的是
AstrBot 解析后的纯文本，不是 OneBot 原始 `raw_message`，所以带 @ 或图片的消息
只比对文本部分。

## 开发

改完插件后需要让 AstrBot 重新加载。注意 AstrBot 的热重载被环境变量守卫：

```python
if os.getenv("ASTRBOT_RELOAD", "0") == "1":
    asyncio.create_task(self._watch_plugins_changes())
```

没设 `ASTRBOT_RELOAD=1` 时文件监视根本不会启动，改代码必须重启容器才生效。
