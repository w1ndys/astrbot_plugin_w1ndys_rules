# astrbot_plugin_w1ndys_rules

AstrBot 群规插件。用中文交流。

## 编码契约

本仓库开发默认启用人话编码契约（土法编码 / 分层交付）：

- `.ohmyagent/skills/human-coding-contract/SKILL.md`
- `.agents/skills/human-coding-contract/SKILL.md`

skill 原文写的是 opt-in，本仓库把它当成默认开发要求，不需要每次再喊触发词。

- 缺背景就停，问用户。不要猜，不要发明协议字段或页面结构。
- 设计顺序：实体 → 数据 → 业务 → 入口。一刀一个逻辑目标。
- 写完本刀、跑检查、**不要提交**。停一次，同一条消息给拟议提交、审阅路径（函数粒度，按层）、本次完成、检查、全部进度、当前下一步。不要在对话里贴完整 git diff。用户回「继续」才提交刚审过的改动。
- 等审时不要偷做下一刀。总体做完就停。
- 入口层只调业务层，不要在 handler 里直接查库。
- 函数（不含空行和注释）≤ 50 行。普通语法，不要多余抽象 / DI / utils 藏逻辑。
- 每个文件、每个函数、每个 `if` 都要有短中文注释（判断目的和后果）。
- 提交前跑已有检查：`python3 -m unittest`。本仓还没有 ruff 配置时，不要假装跑过 ruff，把「无静态检查命令」写进检查项。
- 密钥、token、密码不得进代码、注释、日志、diff 展示和提交信息。
- 未经用户明确允许不要 push。

## 分层

| 层 | 目录 | 职责 |
|---|---|---|
| 实体 | `entity/` | 固定值和数据形状 |
| 数据 | `data/`、`_shared/` | SQLite 与内存快照；`_shared` 只放本插件内重复底座 |
| 业务 | `business/` | 权限、校验、匹配、文案 |
| 入口 | `main.py` | 过滤器、指令、llm_tool，只取群号并调用业务层 |
